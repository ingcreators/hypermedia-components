---
title: Density
description: Switch all controls between comfortable, compact, and dense sizes via a single data-density attribute.
---

The `data-density` attribute on `<html>` (or any ancestor) toggles the
default control height and inline padding across the whole subtree.
Controls that participate in density — currently
[`hc-button`](/hypermedia-components/components/button/) and
[`hc-input`](/hypermedia-components/components/input/) — reference
`--hc-control-height` and `--hc-control-padding-x` through their own
custom properties, so a single attribute change cascades to every
control without re-rendering markup.

## Values (plan §9.3)

| Attribute                         | `--hc-control-height` | `--hc-control-padding-x` |
| --------------------------------- | --------------------- | ------------------------- |
| *(none)* / `[data-density="comfortable"]` | `40px`        | `1rem` (16px)             |
| `[data-density="compact"]`        | `32px`                | `0.75rem` (12px)          |
| `[data-density="dense"]`          | `28px`                | `0.5rem` (8px)            |

Comfortable is the default. The selector `:root, [data-density="comfortable"]`
ensures the values apply unconditionally so an explicit
`data-density="comfortable"` and the absence of the attribute behave
identically.

## Applying it to your page

Set the attribute as high in the DOM as is useful. Most apps want it
on `<html>` so the choice cascades to every control.

```html
<html data-density="compact">
  ...
</html>
```

For a single section of denser UI (e.g. a data table toolbar) attach
it locally:

```html
<section data-density="dense">
  <button class="hc-button">Edit</button>
  <button class="hc-button">Delete</button>
</section>
```

## Why this works

The token build emits component-level custom properties for
height / padding-x as `var()` references:

```css
--hc-button-height: var(--hc-control-height);
--hc-button-padding-x: var(--hc-control-padding-x);
--hc-input-height: var(--hc-control-height);
--hc-input-padding-x: var(--hc-control-padding-x);
```

When `data-density="compact"` overrides `--hc-control-height` to
`32px`, the indirection means every consumer recomputes at the new
value without explicit rules per component.

Per-component customization still works — setting
`--hc-button-height: 56px;` directly on a scope overrides the density
fallback because the per-component property is later in the cascade.

## Size variants are independent

`data-size="sm"` and `data-size="lg"` on buttons / inputs set their
own dedicated variables (`--hc-button-sm-height`, etc.) and are not
affected by `data-density`. They mean different things — "this one
control is a bigger CTA" vs. "the whole UI is laid out tightly."

## CSS variables

```text
--hc-control-height
--hc-control-padding-x
```

These are emitted under `:root, [data-density="comfortable"]`,
`[data-density="compact"]`, and `[data-density="dense"]`. Components
reference them through their own `--hc-button-*` / `--hc-input-*`
variables.
