`hc-input` is applied to the standard `<input>`, `<select>`, and
`<textarea>` elements. State (`disabled`, `aria-invalid`) lives on the
element itself, exactly as in plain HTML.

The `aria-invalid="true"` attribute switches the border to the error
color and changes the focus-ring color. Pair it with a message via
[`hc-field`](/hypermedia-components/components/field/).

## Variants

`data-variant` recolours the border as a validation cue —
`success` (green), `warning` (amber), `error` (red) — the same
vocabulary as [select](/hypermedia-components/components/select/),
[datepicker](/hypermedia-components/components/datepicker/), and the
other form fields. (textarea takes the same attribute.)

<Demo previewClass="hc-preview--col" previewStyle="max-inline-size:24rem;">
  <input class="hc-input" data-variant="success" defaultValue="Looks good" />
  <input class="hc-input" data-variant="warning" defaultValue="Double-check this" />
  <input class="hc-input" data-variant="error" defaultValue="Fix this" />

  <Fragment slot="code">

  ```html
  <input class="hc-input" data-variant="success" value="Looks good">
  ```

  </Fragment>
</Demo>

Prefer `aria-invalid="true"` over `data-variant="error"` for the error
case — it paints the same border *and* announces the state to assistive
tech. `success` / `warning` have no native attribute, so the variant is
the only way to express them. See the cross-component
[Variants matrix](/hypermedia-components/tokens/variants/).

## htmx usage

`hc-input` works with htmx like any other input. The `live-search`
recipe wires the input to send a request as the user types.

```html
<input
  class="hc-input"
  type="search"
  name="q"
  placeholder="Search"
  data-hx-get="/items"
  data-hx-trigger="input changed delay:300ms, search"
  data-hx-target="#results"
  data-hx-swap="innerHTML">
```

## Accessibility

- Always associate inputs with a label. Use `<label for="...">` linked to
  the input's `id`, or wrap the input in a `<label>` element.
- For validation errors, set `aria-invalid="true"` on the input and
  reference the message with `aria-describedby`.
- Do not remove the focus outline. The component replaces the default
  outline with a visible border + box-shadow ring driven by
  `--hc-color-focus-ring`.
- Prefer the native `disabled` attribute when the input must not be
  interactive. Use `aria-disabled="true"` only when the control must
  remain focusable.

## Theming tokens

Component tokens (in `component.tokens.json`):

| Token path                              | Purpose                       |
| --------------------------------------- | ----------------------------- |
| `input.height` / `input.padding-x`      | Default size.                 |
| `input.radius`                          | Border radius.                |
| `input.bg` / `input.fg`                 | Default colors.               |
| `input.border` / `input.focus-border`   | Border in normal/focus state. |
| `input.error-border`                  | Border when `aria-invalid`.   |
| `input.placeholder`                     | Placeholder color.            |
| `input.disabled-bg`                     | Background when disabled.     |
| `input.{sm,lg}.{height,padding-x,font-size}` | Size-specific overrides. |
