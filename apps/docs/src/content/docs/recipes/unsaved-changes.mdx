Losing a half-filled form is the top complaint class in business apps.
`data-hc-dirty-guard` (the auto-installed `installDirtyGuard()`) makes
a form honest about its edit state: `data-dirty` appears on the first
real change, the tab refuses to close silently, boosted navigation
asks first, and a successful save resets the baseline. Client-only —
the save keeps whatever contract the form already follows. Covered by
the [versioning policy](/hypermedia-components/reference/versioning/).

:::note[Setup]
This recipe needs the `installDirtyGuard()` behavior. Install every
behavior at once with `import '@hypermedia-components/core/behaviors';`,
or just this one:

```js
import { installDirtyGuard } from '@hypermedia-components/core';
installDirtyGuard();
```

See [Installation](/hypermedia-components/start/installation/).
:::

:::tip[Scaffold]
`npx @hypermedia-components/cli add unsaved-changes` copies this

## What the guard does

| Moment | Effect |
| --- | --- |
| first focus in the form | baseline snapshot (via `new FormData(form)` — [installFormat](/hypermedia-components/components/input/#grouped-amounts)'s canonical values, so display regrouping is never "dirty") |
| any `input` / `change` | compare → toggle `data-dirty`, dispatch `hc:dirtychange` `{ dirty }` on flips |
| tab close / reload while dirty | the browser's generic prompt (custom strings are ignored by modern browsers) |
| boosted `<a>` navigation while dirty | `window.confirm` with the `dirtyguard.leave` message (localize via [`setMessages()`](/hypermedia-components/fundamentals/i18n/)) |
| the form's own request succeeds | re-snapshot → clean |
| a request from inside the form but not by it | **not** clean — a draft autosaver's draft stays a draft (the autosave recipe follows) |
| native submit | never prompts (`submit` fires only after constraint validation passes) |

## Styling the state

`data-dirty` is a plain attribute — style it in app CSS:

```css
.unsaved-badge { visibility: hidden; }
form[data-dirty] .unsaved-badge { visibility: visible; }
```

A server may also **render** `data-dirty` (a restored draft is unsaved
by definition) — the guard warns from the attribute alone.

## Progressive enhancement

Without JavaScript nothing guards and nothing breaks: the form submits
natively. Pure enhancement by construction.

## Accessibility

- The tab-close prompt is the browser's own dialog.
- Mirror the state into an `aria-live` status line via `hc:dirtychange`
  when a visual badge alone is not enough.
